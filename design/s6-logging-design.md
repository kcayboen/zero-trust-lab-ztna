# S6 — Logging completeness: method (written before the trials, 2026-11-14)

**Table 2 indicator:** percentage of authentication, authorization and access events — granted and
denied — captured in the Windows logs and the OPNsense firewall log. **Threshold: 100 %.**
SOP 3: 5 trials × 100 events; one missed event fails the trial (a miss is a finding, not a re-run).

**Owner decisions this method depends on:** OPNsense evidence = the *local* OPNsense filter log
(2026-11-13, no remote syslog); logging was turned **on** for OPNsense rules 200 and 500 so that
granted cross-zone access to DC01 is an OPNsense event (2026-11-14; snapshot `pre-s6-logging` of VM 202,
config backup `config/opnsense/backup/config-pre-s6-logging-2026-11-14.xml`).

## 1. Ground truth per trial: 100 events, 50 granted / 50 denied

Fixed case file `plan/cases/S6-logging-cases.csv` (generated by `tools/gen_auth_cases.py s6`).

| Family | Events | Granted | Denied | How the event is produced (in-guest, recorded with UTC time) |
|---|---|---|---|---|
| Authentication | 40 | 20 interactive logons that succeed (students on student workstations, instructors on Instructor1) | 20: 10 students at Instructor1 with the correct password (logon right denied, 1385) + 10 unknown accounts (1326) | `config/windows/11-auth-trial.ps1` on each workstation (interactive `LogonUser`) |
| Authorization | 30 | 15 PDP Allow | 15 PDP Deny | `config/windows/06-policy-decision.ps1 -CaseFile …-pdp.csv -Scenario S6` on DC01 |
| Network access | 30 | 15 TCP connections to DC01 domain ports (rules 200/500) | 15 cross-zone TCP connections blocked by OPNsense (rules 300/700) | `config/windows/12-net-trial.ps1` on each workstation, each from a **fixed source port** |

Choices that keep the ground truth clean:
* No wrong passwords for real accounts → nothing is ever locked; badPwdCount untouched.
* `admin-ztna01` is not used for interactive logons (an administrator logon writes two 4624 events).
* Denied network cases are **cross-zone only** — same-VLAN peer traffic is dropped by the host firewall
  and never reaches OPNsense (it is reported separately, owner decision 2026-11-13).
* New scenario label `S6` and new `S6-nnn` CaseIds: earlier labels exist several times in the logs
  (S2 cycles 0–2, dry runs, unit/negtest/evidence decisions).
* Source port = 40000 + 1000 × trial number + case offset (dry run: 46000 + offset) — unique across
  trials, so no TIME_WAIT collision and an exact match key.

## 2. Sinks and match keys ("captured" defined per family)

| Family | Sink (where the event must be) | Captured if … |
|---|---|---|
| Authentication | **DC01 `ForwardedEvents`** (workstation Security log, delivered by WEF) | an event with the expected ID — 4624 *with LogonType 2* for granted, 4625 for denied — from that workstation (`MachineName`), for that `TargetUserName`, inside the trial window. Counted per (workstation, user, ID) key: captured = min(found, expected). |
| Authorization | **DC01 `Application` log**, source `ZTNA-PDP` | event 4100 (Allow) / 4101 (Deny) whose message contains `case=<CaseId>` and `trial=<Tn>` with the expected decision. The PDP runs on DC01 (the collector), so this is the central log. Note for the manuscript: PDP decisions are in the Application log, not the Security log. The `WARMUP` decision is excluded. |
| Network access | **OPNsense `/var/log/filter/` (local)** | ≥ 1 `filterlog` line with direction `in`, the expected action (`pass` / `block`), and the exact (source IP, source port, destination IP, destination port). Blocked TCP may produce several SYN lines (retransmits) — counted once. The automatic `pass out` line on the server VLAN is ignored. |

## 3. Windows and timing

* Trial window = [first case timestamp − 2 s, last case timestamp + 10 s] from the runners' raw CSVs
  (`TimestampUtc`), never from Scenario/Trial labels.
* `Get-WinEvent` `StartTime/EndTime` are not millisecond-precise: query with wide bounds and filter on
  `TimeCreated` exactly (lesson from S1).
* Counting starts ≥ 70 s after a trial ends (WEF max latency 5 s + heartbeat 60 s); ≥ 15 s gap
  between trials.
* OPNsense logs whole seconds and ran ~1 s ahead of the workstations (2026-11-14); the exact port key
  is the primary match and a ±30 s time check the secondary one. **Cycle 0 was counted on the 4-tuple
  only** (the ±30 s check was added afterwards); re-counted offline with the check, all 150 network
  cases still matched — and since ports 41xxx–45xxx had never been used before, no older line could
  have matched. The check matters for any re-run, which reuses the same ports.

## 6. Result (2026-11-14, cycle 0 — no refinement needed)

| | T1 | T2 | T3 | T4 | T5 | Mean | Threshold |
|---|---|---|---|---|---|---|---|
| Logging completeness, 100 events | 100 % | 100 % | 100 % | 100 % | 100 % | **100 %** | 100 % → **PASS** |
| Authentication (40) / Authorization (30) / Network (30) | 100 / 100 / 100 % in every trial | | | | | | |
| Granted (50) / denied (50) | 100 / 100 % in every trial | | | | | | |

* Every match was exact: per (workstation, user, event ID) key found = expected, no surplus; no network
  case showed an unexpected action (e.g. a `pass` where `block` was expected).
* Table: `results/processed/SOP3-S6-logging-completeness.csv` (`tools/sop3_s6.py`); per-case files
  with evidence and the raw sink extracts: `results/raw/S6-logging/S6-cycle0/` (`s6-Tn-cases.csv`,
  `s6-Tn-windows-sink.txt`, `s6-Tn-opnsense-sink.txt`, runner CSVs). Evidence shots 63, 64.
* Dry run first (`dryrun`, source ports 46xxx): 100/100. It exposed one tooling defect — the counter
  compared lab timestamps with the laptop clock (~8 h apart) and would have waited hours; "now" is
  now read from DC01.
* Procedure: `tools/s6_trial.sh Tn` (ground truth on all four hosts) → ≥ 70 s → `tools/s6_count.py Tn`
  → `tools/sop3_s6.py`. Trials ran 10:19–10:24 UTC (lab), 15 s apart.
* **Re-count:** the runners' files on the hosts were moved to `C:\ZTNA\results\raw\S6-cycle0\` after
  counting, so a plain re-run of `s6_count.py` cannot find them; `s6_count.py Tn --offline` re-counts from
  the saved files in `results/raw/S6-logging/S6-cycle0/` (writes `s6-Tn-cases-offline.csv`): 100/100 ×5.
* **Negative control** (`s6_count.py Tn --negcontrol`): one ground-truth row per family deliberately
  broken (user → ghost99, PDP decision flipped, source port → 49999) and matched against the saved
  sinks → **97/100 in every trial, the three missed cases being exactly the three broken ones**. The
  counter can report less than 100 %; the 100 % is not an artefact of a lenient match.
